# Requirements: FlutterRunlet v0.1

**Defined:** 2026-11-12
**Core Value:** 开发者无需打开 VS Code 即可复用项目已有配置完成 Flutter Debug，并在会话结束后按原配置恢复环境。

## v1 Requirements

v0.1 的需求来自 [PRD](../../docs/01-PRODUCT.md)、[技术契约](../../docs/02-TECHNICAL.md)、[UI 规格](../../docs/design/UI-SPEC.md)和[验收矩阵](../../docs/04-ACCEPTANCE.md)。带 A 编号的条目可查对应的可执行场景。

### 上游与原生窗口

- [x] **BASE-01**: 审查 Flutter GUI Runner 的源码、依赖与许可证，记录复用边界，导入的代码保留必要许可及版权。
- [x] **BASE-02**: 原生 App 可启动并打开主窗口、菜单栏面板、设置及独立关于窗口。主窗默认 640 × 580 pt，菜单栏面板宽 404 pt，记录原生控件差异。（A01、A02）
- [x] **BASE-03**: 审查所用原生 API 在暂定最低目标 macOS 15 的可用性和替代路径，验证目标构建。（A31）

### 项目配置与任务

- [x] **CONF-01**: 打开或切换包含 `pubspec.yaml` 的 Flutter 项目，记住最近项目并能重新读取启动配置，显示读取错误。
- [x] **CONF-02**: 读取 `launch.json` 和 `tasks.json` 的 JSONC 注释与尾随逗号，保留配置名称并为无效文件提供位置和原因。（A07、A08）
- [x] **CONF-03**: 仅允许有效的 Dart Flutter Debug 启动。非 Debug 和其他不支持配置仍显示名称与原因，执行层在任务和 Flutter 启动前复验。（A32）
- [x] **CONF-04**: 按契约透传 `toolArgs`、应用 `args` 和旧版 `args` 中明确可识别的 `--dart-define=KEY=VALUE`，保留顺序及原值，对无法映射或冲突的参数阻断运行。（A08、A09）
- [x] **CONF-05**: 解析启动 `program`、`cwd`、继承环境、`env`、`osx.env` 与支持的变量，保留原配置文件和环境值。（A10、A11）
- [x] **TASK-01**: 按 `label` 解析前后置 shell/process 任务，处理各自的参数、目录及环境，安全执行配置的命令。（A08、A11）
- [x] **TASK-02**: 缺失任务、不支持的扩展、后台或依赖任务、不支持的变量及失败的前置任务均有明确错误，阻止 Flutter 启动。（A12）
- [x] **SAFE-01**: Flutter 进程退出后才执行项目指定的后置任务。公开 prod 示例恢复到 test，以任务退出码确认成功。（A13）
- [x] **SAFE-02**: prod 启动前写入持久风险标记。前置任务部分写入后失败或应用异常退出时保留标记，下次启动提供恢复入口。（A15）
- [x] **SAFE-03**: 后置恢复失败时显示阻塞状态，允许重试配置指定的任务，成功后才清除风险。（A14）
- [x] **SAFE-04**: 按规范化项目路径加锁，避免重复 Run 产生冲突。切换项目、启动新环境及退出应用时受前一会话终止与恢复约束。（A16）

### 调试会话

- [x] **RUN-01**: 刷新、选择和验证可用的 iOS 模拟器、Android 模拟器或真机，提示不可用原因及与配置中显式设备的冲突。（A17、A18）
- [x] **RUN-02**: 按项目 FVM、手动 SDK 和系统路径规则解析实际 Flutter/Dart 版本。配置要求的 SDK 无效时说明原因并阻断运行，展示与实际使用一致。（A24）
- [x] **RUN-03**: 启动、停止、热重载和热重启当前 Debug 会话。各操作随生命周期启用，进程退出或设备断线后更新状态并进入适用恢复流程。（A17、A19、A22）
- [x] **RUN-04**: 两个浏览器入口绑定当前 VM Service，重启后更新地址。Inspector 直达不可用时打开已连接的 DevTools 并提示用户进入 Inspector。默认避免持久化完整敏感 URL。（A20）
- [x] **RUN-05**: 从主窗口或菜单栏控制同一会话。关闭主窗口后会话持续，菜单栏状态与操作同步。（A21）
- [x] **RUN-06**: 查看、折叠、复制和清空原始日志。清空后折叠再展开保持清空，仍能接收新输出。（A30）

### 界面与设置

- [x] **UI-01**: 主窗与菜单栏呈现就绪、启动、等待 VM Service、运行、停止、恢复和错误。恢复失败提示及重试入口在日志之外，长名称在锁定状态仍可查看。（A03、A05、A21）
- [x] **UI-02**: 整应用支持简体中文、English 和跟随系统，切换立即生效并记住，布局适配系统深浅色，用户数据和 CLI 原文保持原样。（A05、A23）
- [x] **UI-03**: 设置左导航仅含通用和 Flutter。通用页展示已实现的通用偏好，Flutter 页管理 SDK 来源、路径与 FVM 并展示实际版本。（A04、A24）
- [x] **UI-04**: 在 Flutter 设置运行 `flutter doctor`，查看摘要或原始输出，能识别检测失败。（A25）
- [x] **UI-05**: 关于窗口独立展示真实版本和构建号、上游归属与版权，确认后的链接可用，待确认链接有明确占位。（A04、A26）
- [x] **UI-06**: 接入已验收的 Dock 图标及同源菜单栏 template，检查深浅外观辨识度，并记录原生布局与控件差异。（A06）

### 稳定性与发布验收

- [x] **REL-01**: 验证启动失败、设备断线、任务失败、重复运行、应用退出与强制终止后的恢复流程，运行中退出有明确提示并尝试完成清理。（A14–A16、A22、A28）
- [x] **REL-02**: 验证长时间运行和高频日志下 UI 可响应且内存占用可接受，并回归清空、折叠与新输出。（A27、A30）
- [x] **REL-03**: 在获授权的真实 Flutter 项目复验 dev/test/prod、参数和环境切换，并核对最终 Release 主程序及 worker 的 macOS 15.0 部署目标。2026-11-14 经用户确认取消 macOS 15 运行验收。（A29、A31）
- [x] **REL-04**: 完成适用验收和 G3 视觉确认，备妥 Release 构建、文档、许可证及发布说明。prod 恢复通过后才达到发布门槛。
