# Phase 1 · G1 原生 UI 设计契约

Phase 1 交付可启动的 macOS App 骨架。主窗口、菜单栏面板、设置和独立关于窗口沿用 G0 已验收的布局。配置与任务接入 Phase 2，真实调试和日志行为接入 Phase 3，完整双语、设置功能、项目链接与品牌图标验收归 Phase 4。BASE-01 的上游审计和许可记录按技术契约执行。 [阶段决定](01-CONTEXT.md) · [开发路线](../../../../docs/03-ROADMAP.md) · [技术契约](../../../../docs/02-TECHNICAL.md)

## Design System

| 项目 | 约定 |
| --- | --- |
| Tool | none |
| Preset | 不适用 |
| 组件 | macOS 原生窗口、标题栏、面板、导航、按钮与提示框。SwiftUI 优先，AppKit 按需补充 |
| 图标 | 控件沿用原生符号。关于使用已验收的矢量主标志，菜单栏使用同源单色 template，由系统着色 |
| 字体 | macOS 系统 SF Pro，日志与命令使用系统等宽字体 |

系统窗口控制按钮、焦点、悬停、禁用与选中效果遵循 macOS。图标按钮提供可读的 VoiceOver 名称及悬停提示，键盘焦点按界面阅读顺序移动，禁用动作同样无法经键盘触发。原生行为与画板存在差异时，G1 验收记录写明位置、原因及实际结果。 [UI 基线](../../../../docs/design/UI-SPEC.md) · [设计系统](../../../../docs/design/DESIGN-SYSTEM.md) · [Figma 交接](../../../../docs/design/FIGMA-HANDOFF.md) · [品牌资产](../../../../docs/design/assets/)

## 界面与交互

| 界面 | 布局 | G1 可观察行为 |
| --- | --- | --- |
| 主窗口 | 默认外框 **640 × 580 pt**，无侧栏。自上而下为标题栏、项目、配置与设备双列、同一行四个调试按钮、调试会话、默认展开的日志区域和底部状态。正文左右各 **20 pt** | 标题栏可进入设置与关于。普通启动呈现 Empty。Debug Ready 下可查看示例并触发 Run 的原生演示提示 |
| 菜单栏面板 | 原生面板宽 **404 pt**，高度随内容。项目与会话状态、配置与设备、调试和浏览器动作、打开主窗口／设置／退出依序排列 | 图标打开面板，再点图标或点面板外关闭。与主窗口共享同一状态。关闭主窗后 App 继续运行，可从面板重新打开唯一主窗，Ready 示例仍在 |
| 设置 | 原生窗口外框 **672 × 520 pt**。左侧 **142 pt** 为 G0 参考，仅含「通用」「Flutter」，右侧随导航显示对应页面 | 首次进入「通用」，支持切到「Flutter」再返回。设置控件随对应功能接入后显示 |
| 关于 | 约 **440 × 480 pt** 的独立原生窗口，展示已验收的品牌标志、FlutterRunlet 名称、实际版本及构建号 | 版本与构建号来自当前构建。项目链接按 Phase 4 的 A26 验收 |

主窗与菜单栏状态按下表显示。配置和设备示例值作为只读展示，长值沿用单行尾部省略及悬停查看全名的 G0 规范。会话信息可换行。 [阶段决定 D-01 至 D-07](01-CONTEXT.md) · [UI 基线 §1–5](../../../../docs/design/UI-SPEC.md)

| 状态 | 数据及反馈 | 操作可用性 |
| --- | --- | --- |
| Empty | 普通启动进入，Debug 和 Release 均适用。显示未选择项目，无示例配置、设备、VM Service 或运行日志 | 保留「打开项目」的布局位置，待 Phase 2 项目功能接入后启用。调试与浏览器操作禁用。设置、关于及窗口导航可用 |
| Ready | 专用启动参数仅在 Debug 构建有效。主窗和面板都显示 `sample-flutter-app`、`sample-flutter-app(dev)` 和同一个固定 iOS 模拟器示例，无需读取项目或扫描设备 | Run 可用，点击后弹出原生演示提示。点击「关闭提示」后保留 Ready。Stop、Hot Reload、Hot Restart、DevTools 和 Inspector 禁用。演示 Run 的动作只显示提示框 |

## Spacing Scale

应用正文区域沿用 **4 / 8 / 12 / 16 / 24 pt** 的 G0 间距。主窗正文水平边距为 **20 pt**，可用宽度 **600 pt**。标题栏及工具栏 **52 pt**、调试按钮高度 **26 pt** 是 G0 画板参考，实际高度随系统窗口及原生控件确定。验收分别核对窗口外框和内容区域。 [设计系统 §2–3](../../../../docs/design/DESIGN-SYSTEM.md) · [Figma 交接](../../../../docs/design/FIGMA-HANDOFF.md)

## Typography

| 用途 | 字体与字号 | 字重与行高 |
| --- | --- | --- |
| 正文、字段与调试按钮标签 | 系统 SF Pro，**13 pt** | 常规，系统默认行高 |
| 日志及命令内容 | 系统等宽，**12 pt** | 常规，系统默认行高 |
| 窗口标题与内容标题 | macOS 系统标题样式 | 标题字重与行高由系统样式决定 |

四个调试按钮同排并完整显示当前语言标签。原生标题随系统角色呈现，长会话信息使用正常换行。 [UI 基线 §1、§6](../../../../docs/design/UI-SPEC.md) · [设计系统 §3](../../../../docs/design/DESIGN-SYSTEM.md)

## Color

| 角色 | 取值与使用 |
| --- | --- |
| 主表面 | 系统窗口背景，随系统浅色和深色外观切换 |
| 次表面 | 菜单栏面板、设置导航及内容采用各自的原生表面或系统材料 |
| 主要文字与辅助文字 | 对应系统主文本与次文本颜色。状态用文字表达，状态点只作辅助 |
| 应用强调色 | Ready 的 Run 使用系统强调色。系统原生选中与焦点反馈随系统外观 |
| 品牌 | 关于窗口沿用现有青蓝矢量主标志。菜单栏使用单色 template |

系统窗口背景、原生次表面和系统强调色分别标识主体、辅助区域与 Ready 的 Run。各层所占面积随窗口结构、内容与系统外观变化，G1 按层级清晰度和标签可读性验收。浅色和深色使用同一布局及操作可用性，系统语义色处理禁用样式。 [设计系统 §3–6](../../../../docs/design/DESIGN-SYSTEM.md)

## Copywriting Contract

下表给出 G1 简体中文标签和新增演示提示的建议文案。按当前界面语言显示标签，示例项目名、配置名和设备名保持原样。语言切换与完整翻译在 Phase 4 验收。 [UI 基线 §6–7](../../../../docs/design/UI-SPEC.md)

| 元素 | 文案及行为 |
| --- | --- |
| Empty 标题 | 「未选择项目」 |
| Empty 项目入口 | 「打开项目」。项目打开功能接入后启用 |
| Ready 状态及主操作 | 「就绪」「运行」 |
| 调试及浏览器动作 | 「停止」「热重载」「热重启」「打开 DevTools」「打开 Inspector」 |
| 原生演示提示 | 标题「演示模式」，正文「当前为运行演示。」，按钮「关闭提示」 |
| 窗口入口和设置导航 | 「打开主窗口」「设置」「关于 FlutterRunlet」「退出」「通用」「Flutter」 |
| 关于版本信息 | 「版本」「构建号」，取当前构建的实际值 |
| 运行错误与恢复提示 | 按 Phase 3 的会话和 Phase 4 的完整状态范围验收 |
| 破坏性确认 | G1 不适用 |

## G1 验收

1. **A01** 普通启动核对 Empty。用记录中的启动命令打开 Debug Ready，测量主窗口外框 **640 × 580 pt**，核对四个按钮同排、Ready 的操作状态和原生提示。Release 验证仅呈现 Empty。
2. **A02** 测量菜单栏面板宽度 **404 pt**，核对示例数据和操作可用性与主窗一致。关闭主窗，打开菜单栏面板并重新打开主窗，核对只有一个主窗且 Ready 示例仍在。真实调试会话关闭主窗后的联动留到 Phase 3 的 A21 验收。
3. 打开设置确认首次进入「通用」，切到「Flutter」再返回。打开独立关于窗口，核对品牌、应用名、实际版本和构建号。
4. **A31** 构建验证 macOS 15 部署目标，记录使用的原生 API 可用性与必要替代路径。在当前 macOS 26.7.1 上实测四个界面并记录系统版本。按 D-09，Phase 5 因缺少可用的 macOS 15 环境省略该系统的实机复验，验收记录将该部分标为未执行并注明原因。 [阶段决定 D-08、D-09](01-CONTEXT.md) · [验收矩阵](../../../../docs/04-ACCEPTANCE.md)

| 证据 | 界面 | 外观 | 核对点 |
| --- | --- | --- | --- |
| 1 | Debug Ready 主窗 | 浅色 | 外框与原生结构 |
| 2 | Debug Ready 主窗 | 深色 | 相同布局与状态 |
| 3 | Debug Ready 菜单栏面板 | 浅色 | 面板宽度与共享数据 |
| 4 | Debug Ready 菜单栏面板 | 深色 | 相同布局与状态 |
| 5 | 设置「通用」 | 任选当前系统外观 | 首次打开页与两项导航 |
| 6 | 独立关于窗口 | 任选当前系统外观 | 品牌标志与实际构建信息 |

## UI Considerations

GSD 探针核对 38 项界面状态。11 项有明确验收条件，6 项以 G1 截图或人工检查核对，21 项按表内理由排除。

| 类别 | 界面或元素 | 状态 | 验收条件或理由 |
| --- | --- | --- | --- |
| empty、partial | 项目、配置、设备字段 | ✅ covered | 普通启动显示 Empty，项目、配置和设备均无示例值。Debug 专用参数进入 Ready 后，两处界面显示同一组完整示例。 |
| empty | 主窗日志区 | ✅ covered | 日志区默认展开，Empty 和 Debug Ready 均无实际运行日志。 |
| populated | 关于窗口 | ✅ covered | 独立关于窗口显示已验收的品牌标志、应用名和当前构建的实际版本及构建号。 |
| overflow、long-text | 主窗口 | ✅ covered | 默认主窗中四个调试按钮同排，完整显示当前界面语言的标签。 |
| long-text | 调试按钮 | ✅ covered | 主窗和菜单栏的操作标签可读，禁用动作的标签仍可辨认。 |
| overflow、long-text | 菜单栏面板、只读字段 | ✅ covered | 主窗和菜单栏的长字段单行尾部省略，悬停可查全名。会话信息可换行，面板高度随内容。 |
| overflow、long-text | 设置、关于窗口 | 🧪 backstop | G1 在规定窗口尺寸下通过截图和人工检查，核对设置两项导航、关于的版本和构建号可读。 |
| overflow、long-text | 原生演示提示 | 🧪 backstop | G1 触发 Ready 的 Run，核对原生提示的标题、正文及关闭按钮完整可见。关闭后仍为 Ready。 |
| loading | 四个界面及其控件、字段和日志区 | 已排除 | G1 使用本地窗口与固定演示数据，配置读取、设备检测和会话加载由后续阶段接入。 |
| error | 四个界面及其控件、字段和日志区 | 已排除 | 运行错误及恢复状态按后续阶段验收。G1 若窗口、控件或品牌资源未达到契约，按验收失败记录。 |
| empty | 关于品牌图像 | 已排除 | 品牌标志为随 App 提供的固定资源，验收要求正常显示。 |
| populated、partial、overflow、zero-one-many | 日志列表 | 已排除 | G1 只验证空日志区域的结构。真实日志、长输出、追加、清空与折叠行为按 Phase 3 和 Phase 5 验收。 |
