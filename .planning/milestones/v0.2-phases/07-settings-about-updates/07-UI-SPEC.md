# 阶段 07 · 设置、关于与更新界面规格

以[阶段 07 已确认决定](07-CONTEXT.md)、[v0.2 验收需求](../../v0.2-REQUIREMENTS.md#设置与关于)与[已确认 Figma 原型](../../../../docs/design/FIGMA-HANDOFF.md#v02-界面原型)为依据。本轮在 Figma 桌面端核对了设置三页、独立关于窗口和「设置 / 检查与更新」组件。用本地设计交接定位「03 · 设置窗口」「04 · 关于窗口」，将剩余图层度量和截图索引保存在本地验收目录。

## 设计系统

| 属性 | 约定 |
| --- | --- |
| 组件 | SwiftUI 与 AppKit，沿用窗口和现有行为，按画板定制应用可控的外观 |
| 图标 | 复用仓库品牌资产，链接及控制图标按确认画板匹配形状、尺寸、线宽和基线 |
| 字体 | 按图层读取字体家族、字号、字重和行高，按角色记录中文与英文的字体回退。环境检测原始输出沿用等宽样式 |
| 窗口 | 三张设置画板外框均为 520 × 520 pt，圆角 13 pt。独立关于窗口外框为 400 × 412 pt，圆角 14 pt。画板尺寸包含标题栏，实际截图需分别标记窗口外框和内容区域 |
| 系统行为 | 保留 macOS 键盘导航、辅助功能、窗口管理及原生目录选择器。记录系统绘制差异的具体位置和原因 |

标题区、左栏、表单、切换开关、按钮、品牌区、链接和状态反馈都须按画板近像素级实现。现有系统侧栏、默认 Picker、Toggle、Button 或导航标题在外观有出入时使用自定义样式或控件。设置采用左侧窗口标题，独立关于采用居中标题。保留 macOS 的窗口操作、键盘和辅助功能语义。系统窗口按钮、实际目录选择器及系统绘制的边缘可单独取证，应用可控制的标题区、弹层内外观和内容区按画板核对。

## 结构与组件

| 界面 | 结构及行为 |
| --- | --- |
| 设置公共区 | 主窗口与菜单栏齿轮打开同一窗口。左栏纵向排列「通用」「Flutter」「关于」图标和标签，选中行使用独立底色。实际版本与构建号固定在左栏底部，使用说明文字的字号和颜色 |
| 通用 | 「语言」分组包含「界面语言」及跟随系统、简体中文、English 三项选择。「启动与项目」分组包含登录时自动启动、启动后显示主窗口和记住最近打开的项目。保留已保存偏好、系统登录项状态与启动时待恢复提示 |
| Flutter | 依次为「Flutter SDK」「FVM」「环境检测」三组。SDK 组呈现自动／手动、当前来源、路径、版本与状态。显示与实际运行 SDK 一致。无可用 SDK 时显示原因，禁用环境检查，在允许编辑时保留修正路径入口。检测复用摘要、取消、重试及完整原始输出，超长输出可滚动、选中并查看 |
| 设置「关于」 | 页标题下是一张三段式卡片。首段左侧是标志、应用名、实际版本与构建号，右侧是更新按钮；第二段显示更新反馈；第三段横排三个图标链接 |
| 独立关于窗口 | 居中纵向排列品牌图标、应用名、实际版本及构建号、「轻量 Flutter 运行与调试工具」、更新按钮与反馈。分隔线后是三个图标链接，底部显示 MIT 许可证和 Svame 署名。保留现有许可和上游归属记录 |

两处「关于」共用品牌、版本、更新状态及链接组件，按各自画板布局。带图标的「Github」「使用文档」「项目许可证」分别交给默认浏览器打开已确认的仓库首页、README 和 LICENSE。

## 间距、排版与配色

- 已核对设置「关于」的标题栏高 47 pt，内边距横向 16 pt、纵向 12 pt。下方主体为 518 × 470 pt，侧栏宽 116 pt，侧栏内边距横向 10 pt、纵向 14 pt，正文内边距横向 15 pt、纵向 14 pt。实施时核对通用与 Flutter 的同名组件实例。独立关于的内容区为 398 × 374 pt，横向内边距 20 pt、纵向 18 pt，顶层组间距 15 pt。
- 已抽查更新组件的待检查、检查1、有新版、更新1和完成变体，按钮均为 116 × 30 pt、圆角 6 pt。较长英文和实际版本号先在画板对应位置核对。需要适配时维持主布局和交互信息完整，并记录具体差异。
- 逐状态核对标题、正文、说明文字、版本行、按钮及输出的字号、字重、行高和多行对齐。切换语言后界面文案一致，SDK 路径与原始输出保留原文。
- 已在设置深色画板核对 `background/window` #171E28、`surface/toolbar` #1D2632、`surface/field` #202A37、`surface/selected` #223D50、`border/divider` #2B3848、`border/default` #344252、`text/primary` #F0F5FB、`text/secondary` #B0BDCD、`action/accent` #55CFFF、`text/on-accent` #0B2230。
- 主更新按钮与开启的开关共用强调蓝。深色画板的「检查环境」按钮也使用强调蓝，侧栏选中使用独立底色。开关滑块白色，关闭底色为灰色。分别核对失败、禁用和焦点样式，以及浅色语义配色。

## 文案与更新状态

| 状态 | 展示与操作 |
| --- | --- |
| 待检查 | 「检查更新」及「检查 FlutterRunlet 是否有新版本」。仅主动点击后查询最新正式 Release，跳过草稿和预发布版。调试与恢复期间仍可查询 |
| 检查中 | 旋转指示及「检查中...」。两处同步，禁用重复发起 |
| 已是最新 | 成功读到正式 Release，且它未高于运行中的实际版本时，显示「已是最新版本」 |
| 无正式版本 | 「暂无正式版本可用」，保留「检查更新」入口 |
| 检查失败 | 「无法检查更新」，显示可用的失败原因，提供「重试」以重新查询 |
| 检测到新版 | 「检测到新版本：vX.Y.Z」与带图标的「更新到 vX.Y.Z」 |
| 下载与安装处理中 | 旋转指示及「更新中...」。调试和环境恢复期间可下载、校验。两处同步，禁用重复下载、安装及重复确认 |
| 下载完成，等待安装 | 两处显示更新已下载及暂不可安装的原因。调试、待恢复、恢复失败、恢复记录不可读或受管进程退出未确认时，继续等待 |
| 可以安装 | 首次满足安装条件后主动弹出「安装并重启」，即使两处关于都关了。确认执行时再次核对安装条件。选择「稍后」时本次运行保留更新包，两处均可手动继续，同一下载只主动提示一次 |
| 成功 | 新版进程启动后三处显示实际安装版本与构建号。画板示例仅用于受控数据演示 |
| 下载或校验失败 | 保留当前版本，显示原因及「重试」「查看发布页」 |
| 安装或新版启动失败 | 恢复并尝试启动旧版。旧版启动后显示原因及「重试」「查看发布页」。旧版已恢复但无法自动打开时，由更新流程仍可呈现的界面显示已恢复的 App 位置及「在访达中显示」「查看发布页」 |

「设置 / 检查与更新」组件共有 11 个变体。「检查1–4」「更新1–4」分别提供两种转动指示的关键帧。每组核对视觉尺寸及连续旋转，状态持续时间由真实操作决定。画板「完成」是演示反馈，新版本号在新版实际启动后读取。已是最新、无发布、等待安装、稍后继续和失败分支沿用对应页面的组件及版式，并独立验收。

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |
| --- | --- | --- | --- |
| loading | 更新与环境检测 | ✅ covered | 更新检查和更新中在两处关于同步显示进度。环境检测运行中可取消 |
| error | 更新与环境检测 | ✅ covered | 更新失败按上述操作恢复。环境检测保留失败提示、重试和可用原始输出 |
| empty | 正式 Release 与 Flutter SDK | ✅ covered | 无正式 Release 显示专用状态。Flutter 无可用 SDK 时展示现有状态，不用示例值填充 |
| overflow | SDK 路径、环境输出与英文长文案 | 🧪 backstop | 在实际窗口复核长路径仍可读或查看全值、完整输出可查阅、英文操作标签及版本行不裁切 |
| populated | 版本刷新与共享状态 | ✅ covered | 两处关于共享同一发布和安装状态。重启后两处关于和侧栏统一显示新版实际信息 |
| partial | 已下载但暂时无法安装 | ✅ covered | 调试或恢复期间等待。安全条件满足后主动确认，稍后可由任一关于入口继续 |
| partial | 安装确认期间会话状态变化 | ✅ covered | 弹出确认后若会话或恢复状态发生变化，点击确认也不能触发替换，界面回到等待安装 |
| partial | 两个关于入口的生命周期 | ✅ covered | 从一处发起后切换、关闭并重开另一处，当前查询、下载或等待状态一致。空闲后仅出现一份主动确认 |
| error | 安装回退反馈 | ✅ covered | 分别模拟新版与旧版启动失败。反馈准确区分恢复结果，成功恢复且旧版打不开时展示有效路径和访达入口 |
| loading | 选择 SDK 与环境检测 | ✅ covered | 正在验证手动路径、检测中、取消与重新检测均显示对应状态。项目或 SDK 变更后，旧检测结果不会显示为新环境的结果 |
| error | 登录项与手动 SDK | ✅ covered | 登录项不可更改时保留原因及适用的系统设置入口。手动路径无效时保留可用设置、显示原因，并可重新选择 |
| populated | 两处「关于」的品牌资产 | ✅ covered | 两处直接呈现随 App 打包的品牌资产，无需联网。最终候选检查图标是否实际渲染，避免因缺少资产而出现空白 |
| long-text | 发布版本、说明与辅助操作 | 🧪 backstop | 用真实长度的中英文版本号、构建号与失败说明核对可读性，检查窄空间下更新与链接操作可达 |
| overflow | 设置导航、语言菜单与项目链接 | 🧪 backstop | 键盘及 VoiceOver 操作能读出名称、选中／开关状态和禁用状态。关闭弹层后回到对应控件，长文案不遮住操作 |

## 视觉与交互验收顺序

1. 建立逐状态对照清单，记录 Figma 页面与图层名、状态、语言、外观、逻辑尺寸和截取边界。先补齐剩余图层的字体、行高、图标和浅色样式。对没有对应画板的语言、外观与状态，列出采用的组件和语义样式，并记录实拍证据。
2. 使用相同文案、版本与状态数据在实际 App 取图。Figma 导出与原生截图统一为同一倍数和 sRGB，以窗口或内容边界叠图，并记录关键元素的坐标、字号、颜色和值。逐一核对设置三页、语言选择、环境输出及两处「关于」的原型更新状态。动态图标取对应帧核对，另验证连续旋转。
3. 逐项修正应用可控的几何、配色、控件形状和文字差异。系统窗口按钮、原生目录选择器、字体栅格及真实数据差异记录具体区域与原因，保留原图。整图像素相似度只作辅助，逐项通过后再接入真实更新。设置保存、SDK 来源与实际运行一致、环境检查以及辅助功能同时回归。
4. 用两份隔离构建验证真实替换、重启与三处版本刷新，复验更新状态同步、重复点击、等待时关闭窗口、稍后继续、确认时会话状态变化、下载校验失败、安装回退及旧版自动启动失败。用同一最终候选联验四处界面的中英文和系统深浅外观、可读控件名称、设置与独立关于的原生键盘行为、主窗口及菜单栏的无 Tab 焦点行为、真实运行与环境恢复。
