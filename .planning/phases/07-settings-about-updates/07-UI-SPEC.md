# 阶段 07 · 设置、关于与更新界面规格

以[阶段 07 已确认决定](07-CONTEXT.md)、[v0.2 验收需求](../../REQUIREMENTS.md#设置与关于)与[已确认 Figma 原型](../../../docs/design/FIGMA-HANDOFF.md#v02-界面原型)为依据。当前规格基于仓库记录，尚未直接测量私有画板。实施首项通过本地设计交接访问对应画板，记录各画板及状态、窗口边界、各控件的尺寸与样式，再开始布局。

## 设计系统

| 属性 | 约定 |
| --- | --- |
| 组件 | SwiftUI 与 AppKit，沿用窗口和现有行为，按画板定制应用可控的外观 |
| 图标 | 复用仓库品牌资产，链接及控制图标按确认画板匹配形状、尺寸、线宽和基线 |
| 字体 | 沿用适用的 SF 系统字体及等宽原始输出，具体页面字号、字重和行高按对应画板测量 |
| 窗口 | 设置宽 520 pt，独立关于 400 × 412 pt。设置高度及内容边界按对应画板测量 |
| 系统行为 | 保留 macOS 键盘导航、辅助功能、窗口管理及原生目录选择器。记录系统绘制差异的具体位置和原因 |

标题区、左栏、表单、切换开关、按钮、品牌区、链接和状态反馈都须按画板近像素级实现。系统默认控件外观有差异时，使用自定义样式或控件，并维持操作语义与可读名称。

## 结构与组件

| 界面 | 结构及行为 |
| --- | --- |
| 设置公共区 | 主窗口与菜单栏齿轮打开同一窗口。左栏显示「通用」「Flutter」「关于」，底部以说明文字的字号与颜色显示实际版本和构建号 |
| 通用 | 语言、登录时自动启动、启动后显示主窗口、记住最近打开的项目。沿用已保存偏好及生效时机 |
| Flutter | SDK 来源、路径、版本和状态，FVM 优先设置，环境检测摘要和完整原始输出。显示与实际运行 SDK 一致。无可用 SDK 时显示原因，禁用环境检查，保留修正路径入口。沿用检测、取消、重试和受会话约束的行为 |
| 设置「关于」与独立关于 | 共享品牌、实际版本与构建号、「轻量 Flutter 运行与调试工具」、MIT 许可、Svame 署名、更新状态和图标链接。带图标的「Github」「使用文档」「项目许可证」分别打开已确认的仓库首页、README、LICENSE。保留现有许可和归属记录 |

## 间距、排版与配色

- 按实际设置及关于画板记录标题区高度、侧栏宽度、各组内边距、分隔、圆角和对齐位置。先以对应画板度量为准，已有设计系统的建议值用于画板未定义的共用界面。
- 逐状态核对标题、正文、说明文字、版本行、按钮及输出的字号、字重、行高和多行对齐。切换语言后界面文案一致，SDK 路径与原始输出保留原文。
- 从对应画板记录深浅外观的底色、侧栏选中、边线、文本与状态色。开关滑块始终白色，开启底色使用同款更新按钮蓝色，关闭底色灰色，同时保留可访问的开关状态。
- 更新强调蓝用于开启的开关和主更新按钮。侧栏选中、失败、禁用与键盘焦点分别使用确认稿或系统行为对应的语义样式。
- 视觉定位以设置左栏和右侧页标题、独立关于窗口的品牌区为锚点。规划中列出需实测的画板和文字行高，布局前按画板度量确定数值。

## 文案与更新状态

| 状态 | 展示与操作 |
| --- | --- |
| 待检查 | 「检查更新」。仅主动点击后查询最新正式 Release，两处关于共享状态 |
| 检查中 | 旋转指示及「检查中...」 |
| 已是最新 | 「已是最新版本」，适用于已核对的实际版本 |
| 无正式版本 | 「暂无正式版本可用」，保留「检查更新」入口 |
| 检查失败 | 「无法检查更新」，显示可用的失败原因，提供「重试」以重新查询 |
| 检测到新版 | 「检测到新版本：vX.Y.Z」与带图标的「更新到 vX.Y.Z」 |
| 下载与安装处理中 | 旋转指示及「更新中...」。调试和环境恢复期间可先下载、校验 |
| 等待安装 | 等会话及恢复结束后主动弹出「安装并重启」确认，即使两处关于都关了。选择「稍后」时在本次运行保留更新包，同一次更新只主动提示一次，两处关于均可手动继续 |
| 成功 | 新版进程启动后三处显示实际安装版本与构建号。画板示例仅用于受控数据演示 |
| 下载或校验失败 | 保留当前版本，显示原因及「重试」「查看发布页」 |
| 安装或新版启动失败 | 恢复并尝试启动旧版。旧版显示原因及「重试」「查看发布页」。若已恢复但旧版无法自动打开，显示 App 位置及「在访达中显示」「查看发布页」 |

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |
| --- | --- | --- | --- |
| loading | 更新与环境检测 | ✅ covered | 更新检查和更新中在两处关于同步显示进度。环境检测运行中可取消 |
| error | 更新与环境检测 | ✅ covered | 更新失败按上述操作恢复。环境检测保留失败提示、重试和可用原始输出 |
| empty | 正式 Release 与 Flutter SDK | ✅ covered | 无正式 Release 显示专用状态。Flutter 无可用 SDK 时展示现有状态，不用示例值填充 |
| overflow | SDK 路径、环境输出与英文长文案 | 🧪 backstop | 在实际窗口复核长路径仍可读或查看全值、完整输出可查阅、英文操作标签及版本行不裁切 |
| populated | 版本刷新与共享状态 | ✅ covered | 两处关于共享同一发布和安装状态。重启后两处关于和侧栏统一显示新版实际信息 |
| partial | 已下载但暂时无法安装 | ✅ covered | 调试或恢复期间等待。安全条件满足后主动确认，稍后可由任一关于入口继续 |

## 视觉与交互验收顺序

1. 取得设置三页及独立关于窗口对应画板，记录画板引用、外观、状态和实测尺寸。应用截图与画板用相同逻辑尺寸和显示比例对齐，区分窗口外框与内容边界。
2. 用受控数据走完原型中的更新状态。逐状态保存画板及实际 App 截图，对照布局尺寸、对齐、间距、字样、图标、配色和控件状态。修正应用可控差异，再进入真实更新接入。真实环境检查、设置保存和原生键盘行为同时回归。
3. 接入正式 Release 查询、下载、安装与重启。用两份隔离构建验证替换和真实版本刷新，复验下载等待、稍后、重试及回退。对同一候选完成四处界面双语、深浅外观、辅助功能和真实运行恢复联验。阶段内的安装验收采用本地候选。
