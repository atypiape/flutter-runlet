## Ready 演示入口

**G1 验收时怎样打开 Ready 演示？**

| 讨论选项 | 选择 |
| --- | --- |
| 普通启动显示 Empty，通过专用启动参数进入 Ready | 选定 |
| Phase 1 验收构建启动即显示示例 Ready |  |

**确认结果** 普通启动显示 Empty，使用专用启动参数进入 Ready。两种状态在实际 App 中验收。

**Ready 演示里的 Run 应怎么表现？**

| 讨论选项 | 选择 |
| --- | --- |
| 按 G0 显示可用，点击给出原生演示提示 | 选定 |
| 暂时禁用并记录 Ready 规格差异 |  |

**确认结果** 沿用 G0 的可用态，点击时用原生提示说明当前为演示。实际 Flutter 调试在后续阶段接入。

**Ready 演示需要几组可选数据？**

| 讨论选项 | 选择 |
| --- | --- |
| 固定一组 dev 与 iOS 模拟器 | 选定 |
| 提供多组脱敏示例以演示切换 |  |

**确认结果** 固定一组脱敏 dev 配置和 iOS 模拟器，主窗与菜单栏显示同一组数据。

**Ready 演示入口需要在哪些构建中可用？**

| 讨论选项 | 选择 |
| --- | --- |
| 仅 Debug 构建 | 选定 |
| G1 的 Debug 和 Release 都可通过参数演示 |  |

**确认结果** 仅 Debug 构建接受专用启动参数，G1 验收记录包含可复验的启动命令，Release 正常启动显示 Empty。

## macOS 15 验证

**当前机器是 macOS 26.7.1。G1 的 macOS 15 验收采用哪种安排？**

| 讨论选项 | 选择 |
| --- | --- |
| G1 验证部署目标和 API，在当前系统实测；Phase 5 做 macOS 15 实机复验 | 采纳 G1 安排，调整 Phase 5 实机要求 |
