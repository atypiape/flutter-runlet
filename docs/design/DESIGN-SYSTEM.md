# FlutterRunlet · 设计系统基线 v0.1

状态：**G0 最终人工视觉验收已通过**。以[最终 Figma 设计及播放入口](FIGMA-HANDOFF.md#最终原型与播放入口)作为 v0.1 视觉基线。

## 1. 设计目标

- **macOS 原生**。SwiftUI 优先，AppKit 按需补充。使用原生窗口、标题栏和控件，沿用系统焦点、悬停、禁用和无障碍行为。禁止用 WebView 模拟原生界面，或为了与 Figma 像素级一致而重绘已有系统控件。控件与画板有差异时以系统行为为准，并记录必要的设计偏差。
- **高效紧凑**：不是 IDE；用户只需操作「项目、配置、设备、Run/Stop、DevTools/Inspector」。
- **低噪音**：主窗口无侧边栏；不做功能卡片堆叠、复杂 Tab、多层导航或冗余统计模块。
- **有上下文**：哪个项目、什么配置、哪个设备、在何状态，始终清楚可见。
- **系统化**：沿用 G0.2 的深色层次，通过同一组语义色变量适配系统浅色。使用 SF 系统字体。

## 2. 窗口与信息层级

| 界面 | 默认外框或面板宽度 | 主要内容 |
|---|---|---|
| 主窗口 | **`640 × 580 pt` 窗口外框** | 标题栏；项目；配置和设备双列；四个调试按钮同排；会话；可折叠日志；底部状态 |
| 菜单栏弹出面板 | **`404 pt` 宽**，高度随状态 | 当前项目和会话、配置与设备、调试操作、DevTools/Inspector、打开主窗口/设置/退出 |
| 设置窗口 | `640 × 520 pt` | 128 pt 全高左侧导航，右侧标题随「通用」「Flutter」「DevTools」「关于」切换 |
| 关于窗口 | 约 `440 × 480 pt` | Logo、名称、当前真实版本、简要说明、项目/文档/许可链接 |

主窗口设计含 52 pt 标题栏和工具栏参考高度，对应 640 × 528 pt 的内容布局区域。正文区左右各 20 pt，可用宽度 600 pt。实现时分别核对实际外框和内容尺寸，系统标题栏高度以运行环境为准。

## 3. 排版和颜色

- 字体：系统 SF Pro；命令/日志/路径使用 SF Mono 或 macOS 等宽字体。
- 正文和调试按钮标签 `13 pt`；原始日志 `12 pt` 等宽字。控件以系统原生尺寸为准，设计稿的调试按钮高 26 pt。
- 间距建议以 `8 pt` 为基本阶梯：4 / 8 / 12 / 16 / 24；优先对齐和留白，减少卡片内套卡片。
- 颜色语义：Run 使用系统强调色；青蓝用于已确认的品牌标志。运行、错误和恢复失败使用语义色和文字提示，禁用态有足够对比。
- 阴影与渐变应克制，优先原生材料与纯色/浅色差；不要从效果图硬编码系统蓝背景。
- Figma 使用 `Runlet G0.1 / Appearance` 的 Dark、Light 模式，以及 `Runlet G0.1 / Layout` 的间距与圆角。两个最终原型页共享变量和控件实例；SwiftUI 以系统语义色为准。

## 4. 控件风格

- 项目、启动配置和设备的选择控件外观一致。长名称单行尾部省略，悬停或独立入口可查看全名；运行中即使选择控件锁定，仍可查看全名。不可用配置仍显示名称和原因。
- 运行控制：`Run` 是唯一主操作；运行中禁用 Run、启用 Stop；热重载/热重启为次操作；图标加文字（不可只有颜色）。
- DevTools：两个独立的外链动作「打开 DevTools」「打开 Inspector」，仅在当前会话已连通时正常可用。
- 会话状态：文本优先（就绪/正在启动/运行中/停止中/恢复失败）；状态点作辅助，不要依赖颜色单独表达。
- 会话、日志、恢复提示采用应用专属布局。日志默认展开，支持滚动、折叠、清空与复制，随窗口高度扩展。折叠和展开保留清空结果。恢复失败提示及重试入口在日志之外。

设置表单统一使用原生下拉菜单，当前值显示在菜单按钮上，菜单中勾选当前项。操作按钮与 macOS 原生常规按钮同高，为 24 pt，共用 10 pt 横向内边距和 6 pt 圆角。更换 SDK、检查环境与更新使用强调色。

## 5. 中英文与 macOS 外观

- 可选：`跟随系统` / `简体中文` / `English`（中文 UI）；英文 UI 相应本地化显示。
- **同一时刻只显示当前语言**，禁止标题、设置行、辅助文案写成 `Language / 语言` 等并排形式。
- 默认系统语言；显式选择可覆盖并持久化；支持恢复为跟随系统。
- 不翻译项目/配置/设备名称，也不翻译 Flutter/Dart 原始日志及命令；统一对用户操作提示进行本地化。
- 禁止将语言切换隐藏在状态栏「每次操作必经的路径」中；主设置窗口是首选位置。可有快捷入口，但不需要把所有配置塞入 popover。

## 6. Logo、Dock 与菜单栏图标

使用[已验收的矢量主标志](assets/flutterrunlet-glyph.svg)。保留简洁、扁平的蓝青色加速折线，避免直接复刻 Flutter 官方商标。

**同源符号、两个输出规范**：

1. **App/Dock Icon**：完整方形背景画布（非黑色、没有外围多余透明或黑色），圆角外形按 macOS 规范；图形居中、足够留白但不出现“图标外围又套一圈空白画布”的问题；导出适用于 `.app` 的高分辨率图标与标准尺寸集。
2. **Menu Bar Icon**：使用相同主 glyph 的**单色 macOS template 图像**，简化细线、去渐变、透明通道只表达形状，使系统能适配浅色/深色菜单栏；**不要直接把彩色方形 Dock Icon 缩小放入菜单栏**。系统自动着色的透明通道不同于用户要求避免的 Dock 外围空画布。

Figma 必须提供可编辑 vector 主符号，以及 App/Dock、状态栏两组命名组件；在 `16/18/20/24 pt` 菜单栏缩放预览检查可辨识度。两种图标的形态应一致，不强求同一 bitmap。

## 7. 设计推进门禁

- **G0 最终验收已通过**。最终同步稿包含 640 pt 主窗、完整双语、深浅外观和关键交互状态。
- **G1 整体粗实现**：验证窗口、选择器、控制区、日志、菜单栏能成立，不追每个像素。
- **G2 MVP 可用**：核心启动、任务、设备和 DevTools 正常。G2 后由用户决定是否做有限视觉精修。
- **G3 最终验收**：无功能回归，视觉与 Figma 关键骨架一致，适配中英双语及异常态。

禁止在 G0/G1 为单个图标、小间距无休止打磨而拖延整体流程。
