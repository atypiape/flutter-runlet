## 如何使用

1. G0 设计结果已记录。A01–A06 中适用于正式应用的条目仍按对应 Phase 执行。
2. 每个 Phase 筛选本阶段的条目，先为每项选择合适的自动验证层级。配置、进程和文件副作用可用测试或脚本断言。原生界面和真实设备行为可用对应环境中的自动交互断言。
3. 自动化在适用的环境或构建中覆盖该项全部预期且通过时，直接记录为通过，无需用户重复操作或确认。验收记录关联条目 ID、受测提交或构建、可复现的命令或用例及其结果。GSD 摘要可用 `coverage:` 引用这些证据，UAT 记录如保留该项则标为 `source: automated`。
4. 只有未覆盖的行为交给人工验收，例如需要主观判断的视觉差异，或自动化当前无法操作的原生控件。同一条目部分覆盖时，人工只复核剩余预期。自动检查失败记为失败，环境不可用且无法完成验证时记为阻塞，按矩阵明确不适用的情形单独记录。全自动通过的阶段可直接完成验收。
5. 涉及 prod 的用例先准备可恢复的测试环境和 Firebase 文件基线备份；不要在真实生产项目上无保护地反复试验。
6. 原生系统行为与 Figma 存在差异时，在对应 Phase 的验收记录里注明位置、原因和验证结果。最终 P5 完成所有适用项的覆盖。

**设计状态和实际实现状态分开记录**：看到 Figma 画板不代表程序已经能够运行该流程。
